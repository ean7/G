# Inve.Store

Сайт і продукт **Inve.Store** створюються поетапно. Перед кожним наступним кроком ми спочатку фіксуємо, що саме потрібно власниці продукту, після цього впроваджуємо узгоджене рішення в коді.

## Формат взаємодії

1. **Питання** — перед реалізацією збираємо короткі відповіді щодо цілі, аудиторії, функцій і пріоритетів.
2. **Узгодження** — фіксуємо структуру або список задач, які потрібно зробити в поточній ітерації.
3. **Впровадження** — реалізуємо тільки погоджений обсяг.
4. **Перевірка** — тестуємо результат і формуємо наступні питання.

## Два напрями продукту

### A. Landing page

Лендінг потрібен для залучення потенційних клієнтів, пояснення цінності бізнес-акселератора та збору заявок.

Перша версія landing page містить:

1. **Hero** — коротке позиціонування, головна цінність, CTA для заявки.
2. **Програма** — для кого акселератор і який результат отримує команда.
3. **Переваги** — ключові напрями допомоги: go-to-market, інвестиційна готовність, менторська мережа.
4. **Етапи** — шлях команди від відбору до Demo Day.
5. **Заявка** — форма для першого контакту з командою Inve.Store.

### B. SaaS product

SaaS-продукт потрібен для клієнтів Inve.Store після залучення: кабінет, робота з програмою, матеріалами, прогресом і комунікацією.

Перш ніж реалізовувати SaaS, потрібно окремо узгодити MVP-функції, ролі користувачів, сценарії входу, оплату, приватність даних і технічний стек.

## Маркетингова воронка та аналітика

Основа Inve.Store — наскрізна аналітика для великої маркетингової воронки: івенти, Telegram-бот, оплати, SaaS-кабінет, консалтинг, інвестиції, ERP-інтеграції та управлінські дашборди. Детальна модель описана в [`docs/marketing-funnel.md`](docs/marketing-funnel.md), а система івентів — в [`docs/events-system.md`](docs/events-system.md).

Детальна структура напрямів описана в [`docs/site-structure.md`](docs/site-structure.md), а правила взаємодії — в [`docs/collaboration-workflow.md`](docs/collaboration-workflow.md).
